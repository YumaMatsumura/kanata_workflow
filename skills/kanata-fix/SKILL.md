# KANATA fix

## 読む資料

このSKILL.mdの実体があるディレクトリから2階層上を`WORKFLOW_ROOT`とする。
リンク経由でも実体を基準に`AGENTS.md`を読み、そこに示す共通規約と対象のローカル指示に従う。
この作業では`rules/coding.md`と`rules/testing.md`も読む。

## 実施

1. 対象と初期差分を確認する。指定Issueがあればそのリポジトリと内容を確認する。
2. 再現条件、コード上の根拠、期待動作を調べる。仕様が分からなければ質問する。
3. 一つの根本原因と、その修正範囲を決める。
   問題の探索から任された場合は、指定範囲内の根拠が強く影響の大きい一件を選ぶ。
   同等の候補が複数で選択が重要なら、候補を示して質問する。
4. 最小限の修正と直接必要な回帰テストを追加・変更する。
5. `rules/testing.md`に従って必要な検査を選び、実行するか対象のCI結果を確認する。
   元の問題が改善したか、どこまで確認できたかを明らかにする。
6. 最終diffを読み、`rules/common.md`の「変更した内容を確認する」に従って完了前の確認を行う。
7. 同資料に従い、原因と、確認できた範囲・未確認の範囲を報告して停止する。コミットしない。

## 一件の意味

一件は一つの原因・Issueであり、一ファイルではない。
同じ原因を直すための複数ファイルや関連テストは許容する。
依頼範囲外のリポジトリの編集が必要なら、必要性を説明し追加の許可を確認する。
独立した二つ目の問題へ進まない。設計上の好みを不具合と断定しない。
存在を確認できない「致命的バグ」を捏造しない。根拠が弱ければ要検証と報告する。

## 依頼例

```text
$kanata-fix kanata_coreのjoint_controllerを調べ、致命的なバグがあれば一件だけ修正してください。
```
