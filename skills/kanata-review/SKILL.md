# KANATA review

指定された変更を確認する。改善候補を広く探す調査は`kanata-audit`の用途である。

## 読む資料

このSKILL.mdの実体があるディレクトリから2階層上を`WORKFLOW_ROOT`とする。
リンク経由でも実体を基準に`AGENTS.md`を読み、そこに示す共通規約と対象のローカル指示に従う。
この作業では`rules/review.md`、`rules/coding.md`、`rules/testing.md`も読む。

## 実施

1. 対象リポジトリとGit状態、比較元・比較先を読み取りで確認する。
   未コミット変更では、HEADに対するステージ済み・未ステージの差分と、対象の新規ファイルを確認する。
   ブランチでは指定された比較元との分岐点からの差分を使い、未コミット変更を混ぜない。
   PRではURLと対象リポジトリ、比較元・比較先のコミット、説明と差分を確認する。
   対象や比較範囲を判断できない場合だけ質問する。
2. 対象の版の差分を読み、関連するコード・仕様・利用側・設定・テストを調べる。
   PRとローカルの内容が同じ版とは仮定しない。取得できない箇所は未確認として残す。
3. `rules/review.md`の関係する観点で確認し、候補を整理する。
   検査やCI結果の確認は`rules/testing.md`の調査用の範囲に従う。
4. 報告前に、候補の根拠と適用する規約を再確認し、同じ原因の指摘をまとめる。
   事実と要検証の内容、今回の問題と既存の問題を区別する。
5. 比較した範囲と、確認中に対象の変更が更新されていないか確認する。
   更新されていればその旨を報告し、古い版の結果を現在の版の確認結果として扱わない。
6. `rules/review.md`の報告項目を、`rules/communication.md`の書き方で会話に返して停止する。

## 境界

- コード・設定・コメントや、Git index・ブランチを変更しない。checkoutによる切替も行わない。
- 読み取りのPR参照は扱えるが、レビューの依頼だけでGitHubへのコメント投稿・承認・変更要求・マージは行わない。
- コミット・pushや、レビュー後の自動修正は行わない。修正は別の明示依頼として扱う。
- 固定回数の再レビューや複数エージェント実行は、このSkillの手順に含めない。

## 依頼例

```text
$kanata-review kanata_coreの今の未コミット変更をレビューしてください。修正はしないでください。
$kanata-review kanata_commonの現在のブランチを、mainからの変更についてレビューしてください。
$kanata-review このPRをレビューしてください：対象のPR URL
```
