# KANATA feat

## 読む資料

このSKILL.mdの実体があるディレクトリから2階層上を`WORKFLOW_ROOT`とする。
リンク経由でも実体を基準に`AGENTS.md`を読み、そこに示す共通規約と対象のローカル指示に従う。
この作業では`rules/coding.md`と`rules/testing.md`も読む。

## 実施

1. 対象、初期差分、既存構造と依存先を確認する。
2. 依頼された機能と完了条件を整理する。
   パラメータなら名称、型、単位、既定値、許容範囲、不正値への動作、動的変更の要否を確認する。
   既存コードや明示指示から確定できない仕様だけユーザーに質問する。
3. 変更するファイルとインターフェース、互換性への影響を短く示す。
4. 指定機能と必要な宣言・設定・テストを最小限の差分で実装する。
5. `rules/testing.md`に従って必要な検査を選び、実行するか対象のCI結果を確認する。
6. 最終diffを読み、`rules/common.md`の「変更した内容を確認する」に従って完了前の確認を行う。
7. 同資料に従い、利用上の変更点と、確認できた範囲・未確認の範囲を報告する。コミットしない。

## 境界

依頼されていない機能、別のバグ修正、全面リファクタリングを混ぜない。
公開名や互換性への影響が依頼から確定できない場合は、実装前に確認する。
依頼機能の実装に不可欠な小さな構造変更は含めてよいが、範囲と理由を示す。
使い方や設定を変えた場合は、関連する説明も必要な範囲で更新する。

## 依頼例

```text
$kanata-feat kanata_coreのjoint_controllerに○○というパラメータを追加してください。
```
