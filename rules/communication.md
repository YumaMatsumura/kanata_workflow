# 説明・Issue・PRの書き方

読み手が、上から順に読んで「何のためのものか」「何をすればよいか」を理解できる文章にします。
この資料は、人が説明を見直すときの基準であり、AIが文章を書くときの指示でもあります。

具体的な書き方は[BOOTSTRAP_PROMPT.md](../BOOTSTRAP_PROMPT.md)も参考にしてください。

## 説明する順番

1. 最初に、目的や結果を1〜2文で伝えます。資料なら「何に使うか」、作業報告なら「何が変わったか」を書きます。
2. 読み手が行う操作や、判断に必要な変更点を説明します。
   操作がある場合は、実行する順番に番号を付けます。
3. 確認結果、まだ確認できていないこと、判断してほしいことを示します。
4. 細かな技術説明や長いログは、必要な人が後から読める場所にまとめます。

作業した順番の長い記録より、変更の目的・結果・影響を中心に説明します。
短い回答には、見出しや番号を無理に増やす必要はありません。

## 日本語の書き方

- 会話・Issue・PR・人向けの説明は、日本語の「です・ます」調で書きます。

- 1つの文で伝える内容を絞ります。条件・操作・理由が続く場合は、文を分けます。

- 「何をどうするか」が分かる動詞を使います。「適切に対応する」だけで終えず、確認する対象や行う操作を書きます。

- 見出しも「差分の保全」より「既存の変更を守る」のように、内容を想像できる言葉にします。

- 専門用語が必要な場合は、最初に短い説明を添えます。例：「コミットする変更を選ぶ操作を、ステージと呼びます」。
  すでに説明した用語を毎回説明し直す必要はありません。

- コマンド・ファイル名・コードの名前は、正確な表記を残します。文章を簡単にするために名前や意味を変えません。
  コミットメッセージは[git.md](git.md)の英語の形式に従います。

- 同じ内容の繰り返しや、コードをそのまま読み上げる説明を減らします。

言い換えの例です。実施結果を表す例ではありません。

| 抽象的な表現 | 行動が分かる表現 |
| --- | --- |
| 規約の読み込み状況を検証します。 | AIがKANATAの規約を読めるか確認します。 |
| 設定と実環境の整合性を確保します。 | 設定に書いた名前と、実際のリポジトリ名が同じか確認します。 |
| ステージ済み差分を保全します。 | すでにコミット対象に選ばれた変更を、そのまま残します。 |

## 誰が読む資料か

主な読み手は[README.md](../README.md)で案内します。

- 人向け・人とAIの共通資料には、目的・使う場面・必要な手順を書きます。
  初めて読む人が迷う箇所だけ、理由や具体例を補います。

- AI向け資料には、使う条件・対象範囲・手順・作業を終える条件を簡潔に書きます。
  必要な条件を省かず、人が手順を見直せる文章にします。

- 共通規約は1か所で管理し、他の資料から参照します。同じルールのコピーを増やしません。

## IssueとPR

対象リポジトリにテンプレートがあれば、その項目と順番に沿って書きます。

- Issue：背景、困っていること・期待する動作、対象範囲、何を確認できれば完了かを書きます。
  原因の推測や提案は、確認済みの事実と分けます。

- PR：変更前後の動作、変更理由、影響する範囲、確認結果を書きます。
  冒頭で、今回何を判断してほしいのかを伝えます。

- AIが担当した範囲は、担当欄などで短く示します。共著表記は[git.md](git.md)に従います。

## 図とスクリーンショット

文章だけでは追いにくい部分を補うために使います。小さな変更で毎回用意する必要はありません。

- UIやRVizの見え方が変わる場合は、必要に応じて変更前後の画面を載せます。

- ノードやトピックのつながり、処理や通信の順番が文章では分かりにくい場合は、図を使います。
  値や設定の違いを比べる場合は、表も使えます。

- スクリーンショットは、実際に取得した画面を使います。
  図は実装や確認した内容に合わせ、設計案や説明用の模式図なら、その旨を示します。

- 図や画像には、見るべき点を短く添えます。Issue・PRでは、投稿先から見られる形式で載せます。

## 確認結果の書き方

[testing.md](testing.md)に従い、何を、誰が、どう確認したかを伝えます。
AIやCIが確認したことを、人が確認したものとして書きません。
未実施のテストやレビュー、未取得の画面を、確認済みとして扱いません。

長いログはリンクや折りたたみにまとめ、本文には結果と判断に必要な箇所を書きます。

AIは提出前に、冒頭で目的・結果が分かるか、説明のない専門用語が続いていないか、
実施済みと未確認を区別できているかを読み直します。
