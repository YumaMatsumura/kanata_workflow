# KANATAの配置とROS 2の前提

この資料では、開発PCやCIに置くリポジトリと、KANATAで使うROS 2の前提を説明します。

## リポジトリの配置

ローカル開発では、作業フォルダを`~/kanata_ws`、ROS 2のリポジトリを置く場所をその下の`src/`とするのが標準です。
`kanata_workflow`は`~/kanata_ws/kanata_workflow`に置き、独立したGitリポジトリとして管理します。

共有する設定に、特定のユーザー名やホームディレクトリを固定しないでください。

配置するリポジトリは、行う作業と必要な依存関係に合わせて選びます。次は配置例です。

| 利用場面 | 配置例 |
| --- | --- |
| Jetson（ロボット側） | `kanata_common`、`kanata_core` |
| オペレータPC | `kanata_common`、`kanata_operation` |
| 開発用PCなど | 必要に応じて3つすべて |
| CI・GitHub ActionsでのAI作業 | 対象リポジトリと、その作業に必要な依存先。`kanata_common`単独でも可 |

CIでは、チェックアウト先や一時ワークスペースなど、ジョブの手順に合わせた場所を使えます。
`~/kanata_ws`や、上のPC向けの組み合わせを必須としません。

ビルドや結合テストなどで他のリポジトリが必要な場合は、その依存先も用意します。
必要な依存先は、`package.xml`や対象の検査・CIの手順で確認します。

[config/repositories.json](../config/repositories.json)は、扱うリポジトリの候補一覧です。
一覧のうち、作業に必要なものだけを配置します。使わないリポジトリを置いていなくても、不足として扱いません。

AIは、依頼内容と実際の配置を見て作業します。
置かれたリポジトリやCPUの種類だけで、PCの役割を決めません。

役割が分からない場合は配置状況を報告し、作業を進めるために役割の特定が必要な場合だけ質問します。

必要なリポジトリがない場合は、その旨を伝え、勝手に作成・cloneしません。

`kanata_workflow`自体の修正依頼も扱えます。

## ROS 2と実行環境

- ROS 2はJazzy固定です。環境変数`ROS_DISTRO`の値で、別のディストリビューションへ切り替えません。

- ローカルでROSの環境設定が必要な場合は、`/opt/ros/jazzy/setup.bash`があることを確認して使います。

- OS・依存ツール・Gitの取得先・ビルド方法は、実際の環境と各リポジトリを確認します。
  推測で環境を作り直したり、依存ツールを更新したりしません。

- リポジトリ名とROSパッケージ名は別です。パッケージがどこに属するかは、実際の`package.xml`を見て確認します。

## 既存の名前と動作を守る

新しいROSパッケージ名は、`kanata_...`を基本とします。

既存のパッケージ名・名前空間は尊重します。Autowareを参考にしても、
自作の名前に`autoware_`の接頭辞や`autoware`の名前空間を取り入れる指示とは扱いません。

外部のAutowareパッケージを使っている場合も、名前だけKANATAへ置き換えません。

他のノードやパッケージが使う次の情報は、動作に影響するものとして扱います。

- ノード、topic・service・action、TFのframe_id、メッセージの定数。
- パラメータの名前・既定値・単位、通信品質の設定（QoS）。
- 通信周期、停止条件、制御の順序。

コードを読みやすく整理する作業では、これらを変更しません。

## 複数のリポジトリに関わるとき

- 依存先を読むことと、編集することを分けます。依頼範囲外の編集が必要になった場合だけ、追加の許可を確認します。

- 同じ不具合の修正に複数リポジトリが必要な場合は、まとめて扱えます。無関係な修正は混ぜません。

- Git操作とpre-commitは、各リポジトリで個別に行います。

- Issueは`owner/repository#N`まで確認し、別リポジトリの同じ番号と取り違えないようにします。
  PR本文では、同じリポジトリのIssueなら`#N`と書けます。

- Issueと作業ブランチの対応が不明な場合は確認します。
  複数のリポジトリの作業を1つのIssueで管理する場合も、その方針を先に確認します。

- コミットはリポジトリごとに行います。途中で失敗した場合は完了した範囲を報告します。
  勝手に変更を戻したり、履歴を書き換えたりしません。
